# Gate M1 · repo, empaquetado y límite de confianza

**Exigía:** login con passkey simulado, ningún puerto interno publicado, gateway sin clave SSH,
healthchecks correctos y una imagen reproducible que sirva la consola y proxye al core.

## Passkeys sin cambiar el formato

```
npx vitest run --project unit apps/gateway/test/auth-flow.test.ts
→ 21 passed
```

Con un autenticador falso que genera claves y firmas reales (ES256, RS256 y Ed25519). Comprueba,
entre otras cosas: que el fichero en disco sigue siendo `users.json` v1 con la clave en JWK —que es
lo que permite no re-enrolar en el corte—, que un challenge no se reutiliza, que un origen o un
`rpId` ajenos se rechazan, que sin verificación de usuario no se entra, que un contador de firma
que retrocede se trata como credencial posiblemente clonada, y que las opciones de login no
revelan si una cuenta existe.

## El gateway no puede ejecutar nada

```
npx vitest run --project integration tests/integration/sse-and-boundary.test.ts
→ 10 passed
```

Sin `X-Jarvis-Identity` válida el core responde 401, incluso desde dentro. Una firma manipulada o
caducada tampoco vale. `/internal/health` queda fuera para que el healthcheck de Docker no
necesite la clave, y no cuenta nada más que si el proceso está en pie.

## Imágenes

```
docker build -f deploy/Dockerfile.core -t jarvis-core:dev .       → jarvis-core:dev     355MB
docker build -f deploy/Dockerfile.gateway -t jarvis-gateway:dev . → jarvis-gateway:dev  258MB

docker run --rm jarvis-core:dev node -e "…"
→ node v24.20.0
→ sqlite 3.53.4
```

SQLite 3.53.4 está por encima del mínimo 3.51.3 que exige el ADR-002 (bug de reset del WAL). La
imagen del gateway **no** lleva `better-sqlite3`: sus dependencias se instalan por workspace, así
que no puede abrir la base del core aunque quisiera.

## Compose

```
docker compose -f deploy/compose.yml config                                  → válido
docker compose -f deploy/compose.yml -f deploy/compose.lan.yml config        → válido
```

Sólo Caddy publica puertos. El core no expone ninguno al host y es el único con la clave SSH
montada, de sólo lectura.

# Gate M3 · el trabajo directo es durable

**Exigía:** que reiniciar el gateway no afecte a un run, que reiniciar el core lo adopte desde el
spool, que la pérdida de red produzca un replay exacto, que dos cancelaciones no dejen proceso
suelto, que ningún `seq` se duplique y que Claude y Codex reales pasen un smoke.

## Comando

```
npx vitest run --project integration tests/integration/durable-runs.test.ts
→ 10 passed
npx vitest run --project integration tests/integration/sse-and-boundary.test.ts
→ 10 passed
```

## Lo que se probó de verdad

- **Matar el core a mitad de un run** y levantar otro contra la misma base: adopta la ejecución
  desde la tmux viva, sigue leyendo el spool por el cursor de bytes y termina. Los `seq` que el
  primer proceso había confirmado siguen ahí, con el mismo tipo, y no aparece ninguno repetido.
- **Preparar dos veces el mismo run** —lo que pasaría si el core muriera entre el `ssh` y el
  commit— no lanza un segundo agente: un solo `agent.result` en el event log.
- **Cancelar un agente que ignora SIGINT**: la señal amable no basta, la escalada mata la sesión, y
  el run **no** se marca `cancelled` hasta comprobar que el proceso ya no está. Cancelar dos veces
  es idempotente y no deja tmux suelta.
- **Replay exacto por SSE**: un cliente lee la mitad y se va; otro llega con `Last-Event-ID` y
  recibe estrictamente lo siguiente. Unir las dos mitades reconstruye la secuencia entera sin
  huecos ni repetidos. Desconectar el stream no toca el run: termina igual.
- **Idempotencia de envío**: dos `POST /api/runs` con la misma clave crean un run; la misma clave
  con otra petición devuelve `409 IDEMPOTENCY_CONFLICT` en vez de «hacer lo último».
- **Destino y auditoría coinciden**: lo que se enseña antes de enviar es lo que se guarda en la
  fila del run y lo que afirma la auditoría. El prompt no entra en la auditoría, sólo su tamaño.
- **Estrategia A**: con la sesión en un host sin CLI, el agente corre en el bastión y el prompt
  lleva el aviso de dónde está de verdad; el `cwd` del host de trabajo no se propaga.
- **Salida enorme**: 600 KiB en un solo evento se recortan con marca y tamaño original, y el run
  termina. Antes de arreglarlo, una línea mayor que el trozo de lectura dejaba el run bloqueado
  para siempre.

## Lo que falta para el corte

El smoke con Claude y Codex **reales** (M3-26/27) necesita las CLIs instaladas en un host de
verdad. Aquí los agentes son dobles que reproducen sus formatos capturados; el contrato de
invocación y normalización está fijado por los tests dorados de M0.
